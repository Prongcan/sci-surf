# Nginx deployment and one-week arXiv backfill

## Running services

- Nginx: Docker container `paperignition-nginx`, `--network host`, port 80, restart policy `unless-stopped`. It serves `frontend/dist` and proxies `/api/` plus compatibility routes to `127.0.0.1:8000`. Configuration: `deploy/nginx.local.conf`.
- Backend: `paperignition-backend.service` (systemd, enabled), port `127.0.0.1:8000`. Runtime configuration and local random JWT/service secrets are stored under `/etc/paperignition/` with restricted permissions. The service uses `/opt/paperignition-venv` and the local `ci_user_db`/`ci_paper_db` databases, plus the DashScope API key from the repository's gitignored `.env`.
- PostgreSQL/pgvector: Docker container `pi-verify-db`, port `127.0.0.1:5432`, restart policy `unless-stopped`, persistent volume `pi-verify-db`.
- Frontend: the existing React production build is mounted read-only into Nginx. The older Vite preview on port 4173 is no longer needed for normal access.

## Backfill and verification

- UTC date range: 2026-11-14 through 2026-11-20, inclusive. The orchestrator was run with `--stages fetch_daily_papers --date YYYY-MM-DD` against the local paper database. `lazy_mode=true` fetched metadata and embeddings; per-user blogs and PDF extraction were outside this run.
- arXiv `cs.*` papers by `published_date`: 11-14: 311; 11-15: 321; 11-16: 763; 11-17: 765; 11-18: 789; 11-19: 687; 11-20: 0.
- Final database: 3,636 papers with 3,636 distinct document IDs; 3,636 embeddings, all 1536-dimensional; zero papers missing embeddings.
- `GET /`, `GET /search`, `GET /api/health`, `GET /api/papers/by-date` and semantic search through Nginx succeeded. The 11-19 date manifest reported 687 papers; semantic search returned 3 results.
- 84 unit tests and Ruff passed after the schema and batching changes. Integration tests were deliberately not rerun against the populated test database because their cleanup fixture truncates paper tables.

## Fixes made during backfill

- `scripts/init_all_tables.py` now creates or migrates the `paper_embeddings.updated_at` column required by `RDSDBManager.insert_embedding`. The first 1,395 papers were already stored when this mismatch was detected; `scripts/backfill_missing_embeddings.py` repaired their missing vectors and is safe to rerun.
- `EmbeddingClient.get_embeddings` now sends batches of up to 10 texts, preserves the API's item indexes, and retries missing results individually. The two-item batch request and subsequent backfill succeeded.

## Remaining deployment scope

- This is an HTTP deployment by server IP; domain and HTTPS certificate configuration are not included.
- The local PostgreSQL databases still use the test account and database names. The repository `.env` has a placeholder `DB_HOST` and an empty `DB_PASSWORD`, so this setup uses separate local runtime configuration under `/etc/paperignition/`.
- There is no daily orchestrator schedule yet, and no personalized blogs were generated by this metadata backfill.
